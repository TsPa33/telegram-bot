# Warehouse UX-1 — реалізація затверджених референсів

База: `03d202664713c18f303547adebaed50e204bf6fc`, гілка `feature/carpot-warehouse-mvp`. Тільки frontend та звіт у `/warehouse`; backend, міграції, pricing/matching алгоритми, права, startup, Telegram Bot не змінювалися. Немає push, deployment або записів staging/production.

Прочитано [DESIGN_SPEC.md](DESIGN_SPEC.md), візуально переглянуто всі зображення **00–09** із наданого ZIP. [SHA-256 референсів](reference-manifest.json) фіксують саме переглянуті файли. Зображення 05/08/09 враховані як майбутні UX-2/UX-3: новий drawer, нові рекомендовані-price actions чи bulk workflow не реалізовані.

## Що змінилося

- Картка автомобіля відкривається як основний workspace замість довгого модального вікна. Компактна шапка з реальними полями авто, наявним редагуванням, вкладками «Запчастини», «Загальна інформація», «Історія операцій». Історія — чинний read-only `/audit?vehicle_id=...`, лише за `audit.view`, останні 50 операцій.
- Чотири лічильники: усі позиції поточного плану, з ринковою ціною (A/B/C), рекомендовані (A), без ціни (D або без пов'язаної складської позиції). Вони фільтрують список. Це не покриття всього глобального каталогу. Поки відповідь не отримана або є помилка, невідомі дані не видаються за D; показуються прочерки/помилка. Когорти різних валют не дублюють кількість позицій.
- Пошук за назвою, установчою позицією, OEM та артикулом; категорія, підкатегорія, стан. Пошук OEM використовує чинний paginated `/parts?vehicle_id=...`, а не N+1 читання карток; архівні метадані читаються додатково лише коли вони є в поточному плані. Помилка завантаження явно обмежує пошук за OEM.
- Щільний згрупований desktop-список з шапкою колонок, згортанням категорій, компактними статусами, кількістю, цінами й кнопкою наявного редактора. По 60 рядків із «Показати ще»; статистика рахує весь завантажений план, не лише перші 60.
- На iPhone — картки; пошук і кнопка фільтрів в одному рядку. Статистика та додаткові фільтри згорнуті за замовчуванням і розгортаються без модального вікна. Це зберігає пріоритет списку, як у референсі 06.
- Нове представлення використовує «Рекомендована ціна», «Моя ціна», «Схожі ціни», «Переглянути ціни». B/C не перетворюються на рекомендацію. Розкриті ціни містять суми/валюти/стан та коротке застереження, без provider names, source IDs, причин matching чи ingestion timestamps. Немає автоматичної конвертації або автоматичного market→selling_price.
- Клік власної ціни відкриває **наявний** SellerPriceEditor з незміненими CAS/CSRF/idempotency/replay semantics. Кнопок миттєвого застосування рекомендації з демонстраційного макета не додано.
- Чинні допоміжні інструменти, виключення/повернення та bulk pricing збережені під згорнутими розділами, не є новими UX-3 сценаріями. Наявний detail editor відкривається без нового UX-2 drawer.

## Візуальне порівняння

Після першого огляду скриншотів виправлено успадковані `nav { flex-direction: column }` і `details { max-width: 350px }`, що ламали горизонтальні вкладки й повноширинну таблицю. Виправлено колір статусу, щільність рядків, розташування допоміжних інструментів та перевантажений мобільний перший екран.

Палітра: primary `#2563EB`, sidebar `#151D28`, page `#F7F8FA`, card `#FFFFFF`, text `#172235`, muted `#66758C`, border `#DEE5EF`, success `#E4F8EA` / `#166534`. Нові токени локальні для `.ux1-workspace`. Темний sidebar активується лише коли відкрито цей workspace; на інших сторінках тема повертається до чинної. Системний шрифт та наявна ширина навігації збережені.

Свідомі відмінності від демонстрації: наявний app header/navigation збережені; новий глобальний mobile bottom bar не додавався. Дані показані з локального синтетичного fixture (227 позицій), не скопійовані з макетних 226/XC90/цін. Достовірних фото цих деталей/донора немає — використані нейтральні placeholders, без фотографій або вигаданого fitment із референсу. У колонці автомобіля лише його фактична модель/рік, без вигаданого діапазону покоління.

## Цільові перевірки

`npm run build` — TypeScript/Vite PASS. `node --test tests/*unit.mjs` — **403 passed** (включно з 8 новими тестами presentation). Повний backend regression не повторювався: backend не змінено.

`WAREHOUSE_E2E=1 WAREHOUSE_UX1_ORIGIN=http://127.0.0.1:5198 node tests/ux1-browser.mjs` — локальний production build/preview + PostgreSQL/API fixture Stage 3C. Авторизація fixture лише loopback; реальний Volvo B або Railway не тестувалися.

Перевіряються 1440px та 390px, лічильники/price filters, OEM search, категорії/підкатегорії/статуси, згортання, доступність наявного editor, збереження/повернення ціни, 409 зі збереженням вводу, вкладки, відсутність provider/technical fields у новому рядку, незмінність кількостей/резервів/початкових цін після повернення, відсутність catalogue/stock/bulk apply запитів, відсутність горизонтального overflow і JS errors, ізоляція теми на іншій сторінці. Ручні записи — лише в існуючому спеціальному локальному synthetic fixture; збережені локальні audit events не очищувалися.
