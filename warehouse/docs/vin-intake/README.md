# Додавання автомобіля за VIN — 2026-11-11

Статус: локальний сценарій реалізовано; **live-декодування та staging deployment BLOCKED** через доступ. Не підтверджуємо реальні характеристики двох VIN за тестовими відповідями.

## Реальні зовнішні перевірки

Для кожного VIN виконано один реальний GET до існуючого безплатного NHTSA vPIC `DecodeVinValues`. Обидва завершились **URLError: Tunnel connection failed: 403 Forbidden**. Окремий GET robots.txt FreeVINDecoder повернув той самий CONNECT 403; policy не отримано, збір сторінок не продовжували. Жодної фактичної зовнішньої відповіді з характеристиками не отримано. Інший тестовий VIN як основний не використовувався.

| Характеристика | YV4L12RK6N1970668 | YV4A22PK2G1092943 |
|---|---|---|
| Виробник / модель / покоління | UNVERIFIED | UNVERIFIED |
| Рік / кузов / кількість дверей | UNVERIFIED | UNVERIFIED |
| Модифікація / комплектація | UNVERIFIED | UNVERIFIED |
| Двигун / код / об’єм / потужність | UNVERIFIED | UNVERIFIED |
| Паливо | UNVERIFIED | UNVERIFIED |
| КПП / код КПП / привід | UNVERIFIED | UNVERIFIED |
| Завод / ринок | UNVERIFIED | UNVERIFIED |
| Причина | CONNECT 403 | CONNECT 403 |

Жодних характеристик не виведено з VIN-циклу, очікуваної моделі, попереднього донора чи fixture. Схожі модифікації локального довідника не є доказом VIN-fitment. Автоматичне доповнення з довідника без точного підтвердженого зв’язку не виконувалось. Доступний окремий чинний вибір із глобального каталогу, але він не видається за VIN-декодування.

## Що реалізовано

- «Автомобілі → Додати автомобіль» тепер відкриває існуючу VIN-форму як основний сценарій. Залишено ручне додавання та альтернативний вибір із каталогу.
- Формат 17 символів без I/O/Q; lowercase нормалізується на backend. Старі відповіді декодера не заповнюють форму після зміни VIN.
- NHTSA vPIC та незалежний fallback FreeVINDecoder з robots gate, timeout і лімітом відповіді. Відмова NHTSA більше не блокує спробу другого безплатного джерела.
- Vincario не викликається в цьому швидкому сценарії навіть при наявних credentials: платне джерело не активували й не тестували.
- Дані згруповано: автомобіль, двигун, трансмісія, кузов/ринок; усе редагується. Позначення «Повідомлено джерелом», «Не визначено», «Змінено вручну» не прирівнюються до factory verified.
- Явне підтвердження перед створенням. При недоступному декодері можна завершити ручне введення без вигаданих значень. Обов’язкові лише марка, модель і коректний рік; VIN необов’язковий для ручного сценарію.
- Виправлено double-escaped drive regex: `AWD`, включно з «Повний (AWD)», більше не блокує збереження. Виправлено аналогічний regex consistency-check об’єму.
- POST створює тільки Vehicle та чинну Operation історії створення, не генерує список розбору або складські Part.
- Перехід до картки збереженого автомобіля. Повторний VIN у workspace повертає 409 і кнопку відкриття існуючої картки; перевірка включає archived і нормалізацію історичного case/whitespace.
- Create/update серіалізовані чинним account lock, тому конкурентні POST не створюють дублікати VIN. Між workspace однаковий VIN допустимий. Старі дублікати не видаляються й не об’єднуються.

## Автозаповнення і збереження

NHTSA, коли доступний, може заповнити: марку, модель, рік (лише з model та без неприйнятного error), EngineModel, об’єм, паливо, КПП, привід, кузов, комплектацію, циліндри, кВт/к.с., двері, серію, тип автомобіля та місто/країну заводу. FreeVINDecoder доповнює тільки явно повернені поля, не перезаписує конфліктні непорожні дані. Конфлікти показуються користувачеві.

Покоління, точна модифікація, engine code, transmission code, ринок не виводяться з припущень; за відсутності доказу лишаються для ручного уточнення. Кожне поле доступне для редагування. EngineModel не переіменовується автоматично на підтверджений код двигуна.

Стандартні Vehicle-поля отримують основні характеристики. Додаткові характеристики (кузов, потужність, двері, код КПП, ринок тощо), копія нормалізованої відповіді, field_sources, конфліктні альтернативи, загальне джерело й час запиту зберігаються в `vin_details`. Це **безпечний структурований snapshot**, не повний vendor payload. JSON має whitelist ключів і ліміти розміру/значень.

Snapshot надходить разом із підтвердженою користувачем формою, тому сервер явно позначає trust `user_confirmed_reported_not_factory_verified`. Це не криптографічно засвідчена відповідь постачальника і не автоматично verified VehicleConfiguration. `decoded` — історична запропонована відповідь; поточні стандартні Vehicle-поля мають пріоритет після подальшого ручного редагування. Усі отримані підтримувані характеристики зберігаються для майбутньої роботи; генерація каталогів не реалізується в цій задачі.

## Міграція і безпека

Єдина additive head `08b72c9d4e16`, parent `f7a10b8c43d2`: лише `vehicles.vin_details JSON NULL`, без backfill, DML, перейменування колонок, індексів, унікального обмеження на історичні дані чи змін stock/finance. Downgrade блокується, щоб не видалити збережені snapshot. Новий head додано в існуючі frontend readiness allowlists.

Міграція виконана **тільки на окремих localhost:55441 `_test` БД**. На Railway не застосовувалась. Перед deployment потрібно підтвердити staging bindings і штатний API startup migration; повторно вручну мігрувати після startup не можна.

## Перевірки

- Цільові backend VIN/normalization tests: **15 PASS**, включно з concurrency, isolation, preservation старого донора/Part та additive migration.
- Browser: обидва **задані VIN** перевірені на явно позначених offline відповідях з реальним локальним PostgreSQL збереженням: повні/часткові дані, ручне уточнення, reload, збереження додаткових полів, duplicate, invalid VIN, manual fallback, без JS errors. Це не live-декодування й не staging QA.
- Frontend `npm run build` PASS (штатний prebuild: 217 PASS); повторні фінальні tsc/Vite перевірки не запускають зайвий великий набір тестів.
- Додатковий `test_quick_vehicle.py`: 8 PASS / 2 FAIL. Обидва failures — історичні downgrade-тести, що намагаються повернути весь сучасний schema chain до `a84d2c19e705`; forward-only міграція правильно відмовляє у видаленні VIN evidence. Ці два тести не оголошуються PASS і не підміняються результатами основного сценарію.
