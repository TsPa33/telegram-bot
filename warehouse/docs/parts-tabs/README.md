# Розбір та налаштування запчастин

Один збережений план і ті самі складські ідентифікатори використовуються у двох вкладках. Контролер залишається змонтованим під час перемикання.

- **Розбір і запчастини:** усі корпоративні категорії рівними плитками, горизонтальні масові дії, таблиця вибору/назви/статусу/фактичної кількості/дій. Статистика, бічна панель, номери та переклади прибрані з операційного списку.
- **Налаштування запчастин:** категорія, OEM, артикул і виробник; фільтри присутності номерів, пошук у безплатно відновлених збережених варіантах, ручні назви й переклади. Після відкриття варіантів кількість альтернатив виключає призначений номер. До завантаження показується фактична загальна кількість збережених варіантів.
- Підтверджена модифікація визначається за збереженим K-Type, а не за маркою/роком. Використовуються наявні описи та підтверджені одиниці характеристик.
- Номери не створюють фізичних складських карток. Для деталі без картки призначення недоступне: спочатку явне додавання в операційному списку. Збережені відповіді доступні незалежно від наявності картки.

## Перевірки

- `npm run build`: PASS, включно зі штатним prebuild (217 тестів).
- `node --test tests/parts-tabs-unit.mjs tests/vehicle-workspace-unit.mjs tests/catalogue-stabilization-unit.mjs`: 20 PASS.
- `WAREHOUSE_E2E=1 node tests/parts-tabs-browser.mjs`: PASS, Chromium, desktop 1440px / iPhone 390px. Окрема локальна тестова PostgreSQL та mocked provider; реальних зовнішніх API-запитів немає.
- Перевірено порядок вкладок, однакові плитки, спільний стан вибору, незмінність складу при перемиканні, відновлення варіантів, призначення до існуючої картки, явне додавання 1 шт., OEM, ручну назву, фільтри, reload, відсутність overflow і JS errors. Для нового донора спочатку пропонується модифікація; платне підтвердження не виконується.

## Межі

Backend, міграції, платежі, авторизація та складські транзакції не змінені. Автоматичний OEM endpoint не підтверджений і не імітується. Модель не підтримує окремого збереженого вибору номера для плану без складської картки. Пошук невідкритих варіантів запускається явно та читає лише вже збережені відповіді. Старі browser-сценарії об'єднаного екрана не є прийманням нової структури; актуальний сценарій — `parts-tabs-browser.mjs`.

Railway staging deployment/QA перевіряються окремо: локальні результати не підтверджують staging. Очікується Web Auto Deploy; backend redeploy і міграції не потрібні.
