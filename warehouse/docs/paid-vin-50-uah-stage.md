# CarPot · розширений VIN-пошук 50 грн — підготовчий пакет

## Що реалізовано

- Кнопка під результатами безкоштовного VIN-пошуку й серверна пропозиція `GET /api/v1/vehicles/vin/paid/quote?vin=...`.
- Незмінна на клієнті ціна: **5000 копійок / 50,00 UAH**, product `warehouse.vin.enrichment`, явне підтвердження.
- Заздалегідь виділений `POST /api/v1/vehicles/vin/paid/confirm`: приймає нормалізований 17-символьний VIN, `request_key`, суму, валюту та `confirmed`; перевіряє їх, але **завжди відповідає 503** до окремого підтвердженого релізу.
- Доменний контракт `vin_paid_contract.py`: визначення тільки нових корисних полів, стабільні ключі для резерву/захоплення/звільнення коштів, дозволені переходи стану; повторні події не змінюють фінальний статус.
- Жодного виклику платних VIN API, жодного списання, резерву, транзакції або створення паралельного балансу у Warehouse.
- Безкоштовне додавання автомобіля залишається доступним.

## Чому реальну оплату не вмикали

Поточний `bot/billing/wallet.py` працює **лише у sandbox** й прямо забороняє production topup/reserve/capture/release. Warehouse має лише проєкцію прав; централізований Billing є єдиним джерелом фінансової правди. Обхід цього обмеження створив би ризик подвійного списання або фіктивного залишку.

## Контракт майбутнього backend-оркестратора (перед увімкненням)

1. Client: VIN + confirmation + fresh UUID request key; quote отримано з сервера; власник або явно дозволена роль. **Ціну визначає сервер**.
2. Warehouse: перевірка tenant/actor, строгий VIN, атомарний запис унікального `(billing_account, VIN, product)` або idempotency operation, повторний запит повертає чинний результат; не створювати дубль платного виклику.
3. **Cache-first:** спочатку пошук уже оплаченої й дозволеної до збереження відповіді за `(billing_account, VIN, provider_version)`. Для дубліката не резервувати кошти. Термін зберігання визначає ліцензія провайдера.
4. Central Billing: `reserve(5000 minor UAH)` під ключем `vin:reserve:...`, із глобальним блокуванням рахунку, перевіркою балансу й журналом подвійного запису. Без успішного резерву — **не звертатися** до провайдера.
5. Лише після гарантованого резерву запустити платний VIN через спеціальний gateway із provider-side request ID; захистити від автоматичних повторних платних викликів при таймауті.
6. Якщо отримано хоча б одне нове підтверджене корисне поле — `capture(5000)`; якщо немає, таймаут або невідома відповідь — `release(5000)`. Якщо зовнішній виклик може бути оплачений провайдером, врахувати вартість як збиток компанії.
7. `capture` / `release` зберігають фінансовий receipt у центральному Billing. Якщо payment status невідомий, не повторювати дебет без reconciliation. Повторна подія має стабільний ключ і незмінний результат.
8. Після успішного capture зберігати лише дозволені ліцензією поля, snapshot/provenance/conflicts/expiry. Не перезаписувати вручну підтверджені характеристики. Прийняття нового поля — не доказ заводської комплектації.
9. Окремий фінансовий audit (workspace, actor, VIN fingerprint, provider request key, reserve/capture/release IDs, cost, result/hash, timestamps). Не друкувати VIN, ключі або платіжні дані в публічні логи.
10. Операції `reserved` старші за TTL повинні оброблятися reconciler, а не мовчки списуватися чи повертатися без перевірки стану провайдера.

## Тести перед увімкненням

- Два паралельні запити того самого VIN: максимум один reserve / один платний provider call.
- Повтор запиту після втрати HTTP-відповіді не створює нового резерву.
- Помилка paid provider або відсутність нових корисних полів: один release.
- Нові корисні поля: один capture; повтор події не створює нової транзакції.
- Недостатньо коштів, чужий workspace, прострочена сесія, неправильний CSRF, зміна ціни: відмова.
- Ревізія кешу/ліцензій, сертифікат provider gateway, захист від billable retries.
- Звірка транзакцій та ліміти витрат на місяць.

## Межі пакета

**Готово до staging:** тільки безпечна UI-пропозиція й заблоковане підтвердження, офлайн-контракт і тести.
**Не готово до real charge:** централізована фінансова операція й gateway платного VIN; їх потрібно впровадити після окремої перевірки провайдера та фінансового контракту.

Реальний VIN пошук лишається безкоштовним; Vincario та всі інші платні API не викликаються.
