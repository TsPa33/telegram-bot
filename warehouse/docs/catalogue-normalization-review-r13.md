# CarPot Warehouse — нормалізація каталогу: пакет на перевірку (R13)

**Середовище:** `warehouse-staging`, тільки читання. **Статус:** пропозиції, не застосовані зміни.

## Джерела та обсяг
- PostgreSQL staging: `categories`, `parts`, `dismantling_catalog_types`, `catalogue_entities`, `canonical_types` та зв'язки зі складом.
- Початковий аудит 01.11.2026: 3 855 вузлів `categories`, 590 груп точних збігів за нормалізованою назвою в одному просторі/батьківському ID/рівні; 15 444 позицій реєстру назв. Ці числа є **підсумком до R13**, повторний запуск оновлює поточні значення.
- `catalogue_ua_proposals_v1.json`: точні пропозиції назв, а не операції `UPDATE`.

## Доступ до повних таблиць
Увійти під **адміністратором платформи** на staging (не достатньо ролі директора окремого складу). Захищені CSV-експорти:
- `GET /api/v1/catalogue/admin/audit/duplicate-review.csv` — всі члени кожної групи, ID, походження, посилання, ризик і рішення `pending`.
- `GET /api/v1/catalogue/admin/audit/catalogue-mapping.csv` — всі початкові назви, рекомендовані українські відповідники й статус.
- `GET /api/v1/catalogue/admin/audit/summary` — кількість груп за ризиком, якість назв та інша агрегована аналітика.

## Що означають класи ризику дублювання
| Risk | Опис | Рекомендована дія |
|---|---|---|
| `linked_stock` | Одна/кілька категорій мають прямі посилання із наявних складських записів | Залишити ID; аналізувати залежні дані першочергово |
| `has_children` | Дочірні категорії використовують один або більше ID групи | Порівняти піддерева, не об'єднувати лише за назвою |
| `cross_source` | Назва однакова, записи надійшли з різних джерел | Зіставити ключі та походження |
| `unreferenced_candidate` | У перевірених `parts` немає активних посилань і прямих дітей | Лише ручна перевірка; інші зовнішні ключі та історія можуть існувати |

**Жоден клас не означає дозвіл автоматично видалити або об'єднати ID.**

## Погодження українських назв
- `translation_proposal` — точна мовна пропозиція; потребує ручного погодження словника.
- `review_hierarchy` — можлива зміна верхнього розділу; **не є синонімом**. Наприклад, «Двигун» належить до «Силового агрегату», але ці терміни не тотожні.
- `dictionary` — словник Aleto; зберігати шлях і оригінальну назву.
- `review_context` — можливий функціональний синонім; перевірити монтаж, сторону, перед/зад і характеристики.
- `unmapped`, `language_review` — без підтвердженого українського відповідника, залишати первинне значення.

Тільки **повний збіг назви зі словником** пропонує нормалізацію. Підрядковий переклад і нечітке об'єднання назв не застосовуються.

## Заборонені автоматичні дії
- `UPDATE/DELETE` для `categories`, `parts`, донорів, імпортованих джерел та фінансових таблиць.
- Об'єднання `source/external_key`, OEM, складських залишків, історії операцій.
- Перенесення правдивої сумісності запчастини між моделями лише за однаковою назвою чи OEM.
- Перепризначення дочірніх категорій/складських позицій без окремого `preview` та погодженого плану міграції.

## План застосування (окремий етап, зараз НЕ виконується)
1. Адміністратор позначає `approve/reject/requires_evidence` для кожної групи.
2. Формується проект відповідностей `source ID → canonical ID` зі збереженням сирих джерел.
3. Генерується dry-run diff із посиланнями та можливістю відкату.
4. Після явного підтвердження — застосування на staging, regression tests, аудит diff. Production лише за окремим рішенням.

## Технічна безпека
- Експорт не створює записів і працює в окремій транзакції PostgreSQL `READ ONLY`.
- Доступ має лише власник із `WAREHOUSE_CATALOG_PLATFORM_ADMIN_IDS` за діючою сесією.
- Обидва CSV мають заголовки та кодування UTF-8 BOM для відкриття в Excel. У новому duplicate-review.csv небезпечні початки клітинок екрануються.
