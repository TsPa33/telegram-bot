# CarPot Catalogue Import v2

## CSV

UTF-8 (BOM дозволено), роздільник — кома, стандартне CSV quoting. Рядок заголовків обов'язковий. Дублікати/невідомі колонки, неправильна кількість значень і порожній файл відхиляються. Порядок колонок довільний.

Обов'язкові колонки й значення:

| Колонка | Значення |
| --- | --- |
| `schema_version` | `2` у кожному рядку |
| `source` | Стабільний lowercase ключ провайдера, наприклад `aleto` |
| `source_article` | Стабільний артикул джерела, 1–150 символів; OEM не замінює артикул |
| `manufacturer`, `model` | Непорожні назви, до 100 символів |
| `category`, `subcategory` | Непорожні назви, до 200 символів |
| `part_name` | Власне найменування деталі, до 1000 символів; не підставляйте автоматично назву підкатегорії |
| `source_url` | HTTPS URL без username/password; для `aleto` лише `aleto.ua` / `www.aleto.ua` |
| `observed_at` | ISO-8601 з timezone, наприклад `2026-10-25T12:00:00+00:00`; нормалізується до UTC |

Необов'язкові колонки можна пропустити; необов'язкові значення можна залишити порожніми:

- `generation` — назва покоління, до 100 символів. Порожнє покоління не зливається з відомим поколінням автоматично.
- `year_from`, `year_to` — чотиризначні роки 1886–2100; початок не перевищує кінець. Це відомості джерела, **не верифікована сумісність**.
- `oem` — вихідний OEM до 1000 символів; не виконується небезпечне автоматичне розбиття/злиття кодів.
- `condition` — стан джерельної пропозиції, до 200 символів.
- `side`, `position` — явні ознаки до 100 символів. Відсутні не вгадуються з тексту.
- `price_uah`, `price_usd` — невід'ємні десяткові числа, максимум два знаки після крапки, менше `1000000000000`. Порожнє — NULL, не нуль. NaN/Infinity/негативні/зайва точність відхиляються. Валюти фіксовані назвами колонок, конвертації немає.

Універсальне значення `source` не запускає запитів до мережі. URL використовується лише як посилання джерела. Warehouse не парсить сайти і не виконує вкладений код.

Кожен рядок означає спостереження конкретної пропозиції та її зв'язок із моделлю/таксономією. Один артикул може повторюватися для різних моделей, таксономій і дат. Незмінні повтори не дублюють записи; суперечливі властивості або різні ціни за одну дату блокують автоматичне зіставлення.

## ZIP

Рівно два файли у корені: `manifest.json` та CSV. Немає підкаталогів, symlink, encrypted entries, дублікатів і сторонніх скриптів. Manifest має рівно три поля:

```json
{"schema_version":2,"file":"catalogue.csv","sha256":"<SHA-256 точних байтів CSV, включно з BOM>"}
```

Після зміни CSV перевирахуйте SHA-256. Система перевіряє фактичні байти, а не назву файла. ZIP не розпаковується у довільні filesystem paths.

## Aleto v1

Окремий адаптер приймає початковий SQLite або його GZIP, включно з наданим пакетом 7 246 пропозицій. Використовується існуючий валідатор v1. Додатково заборонені SQLite views/triggers/virtual tables і сторонні таблиці. Лише readonly SELECT/PRAGMA над staging-таблицями; ніяких вкладених скриптів.

Моделі v1 залишаються Volvo XC40/XC60/XC90; наступні марки й моделі передавайте у форматі CSV/ZIP v2. Перевірений український словник v1 застосовується до його підкатегорій. `Комп` зберігається як невирішена відповідність. Тип деталі отримує повну джерельну назву й OEM, а не назву підкатегорії. V1-адаптер не стверджує fitment за роком і не виводить side/position евристично.

## Ліміти та відтворюваність

JSON control requests (preview/apply) до 4 MiB до JSON-декодування; binary upload до 16 MiB; сумарний expanded ZIP/GZIP до 64 MiB; decompression ratio до 100; до 50 000 рядків; CSV-поле до 4096 символів. Нормалізований payload до 64 MiB. Обмеження перевіряються до запису у каталог. Бінарний upload читається обмеженим stream **після** автентифікації, CSRF і platform-owner перевірки.

Job зберігає SHA-256 оригінального upload і окремий SHA-256 нормалізованих валідованих рядків. Ці рядки зберігаються в PostgreSQL, не в браузері і не у тимчасовому файлі. Preview й apply використовують саме цю версію. Новий файл — новий job; нові ручні рішення — новий preview/token. Перші 200 невирішених відповідностей показуються за один раз; після їх вирішення побудуйте preview знову. Максимум 10 000 ручних рішень на job; більші набори слід розділяти на файли.
