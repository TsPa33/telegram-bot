# UI-1 — спільна візуальна система Warehouse

База: `8ae56ad180a2e4fe5647b9955139b4011493698e`. Frontend-only: структури сторінок, App routes, права, авторизація, обробники, backend та схема БД не змінені. Push/deployment не виконувалися.

Палітра взята із затверджених UX-1 [DESIGN_SPEC](../warehouse-ux1/DESIGN_SPEC.md) та зображень 00–09. `tokens.css` — єдине місце визначення semantic color roles, включно з темним sidebar, синім primary, нейтральними поверхнями та зеленим success. Старі CSS aliases посилаються на ті самі токени. Власну палітру й умовне перефарбування sidebar з `warehouse-ux1.css` прибрано; геометрію таблиці, статистики, фільтрів і mobile cards збережено.

`design-system.css` задає спільний sidebar/topbar, активні/неактивні пункти, профіль, кнопки, поля, focus, checkboxes, статуси, cards, tables та dialogs. На низькому екрані меню прокручується; маршрути й поведінка відкриття/закриття залишилися попередніми. Локальні стилі розділів лише використовують спільні кольори; сторінки Sales/Inventory/Orders/Statistics/Team/Settings/Catalogue Admin не перебудовувалися. У вузькій наявній price card дозволено перенесення тексту, щоб блоки цін не перекривалися. Backdrop мобільного меню має окрему роль overlay, тому загальний button hover не перефарбовує його у світлу заливку.

У спільному представленні цін прибрані видимі назви постачальника/артикули джерел із підписів посилань: «Переглянути оголошення» / «Переглянути ціни». Рекомендовані й схожі ціни підписані окремо. URLs, докази backend, суми, вихідні валюти та save semantics не змінені; FX немає.

## Перевірки

- `npm run build` — PASS. `node --test tests/*unit.mjs` — **411 passed**, включно з перевірками контрасту спільних ролей і відсутності приватної палітри UX-1.
- `WAREHOUSE_E2E=1 node tests/ui1-browser.mjs` — **1440×1000 та 390×844 PASS**, 13 маршрутів на кожній ширині: робочий простір, автомобілі, склад, продажі, замовлення, статистика, команда, налаштування, Catalogue Admin, довідник, аудит, архів, розширений склад.
- Перевірено однакові кольори shell/меню, читабельний текст неактивних посилань, mobile menu/navigation, відкриття й закриття чинних форм автомобіля та замовлення, combobox/select/checkbox, UX-1 stats filters/OEM search/згортання/власні та рекомендовані ціни. Немає JS errors або horizontal overflow. Після ручного огляду виправлено контраст старого правила sidebar та перенесення тексту price cards; фінальні скриншоти переглянуті.
- Тест — лише production build/preview та **наявний локальний synthetic fixture**, не Railway і не реальний Volvo B. Форми не надсилалися; каталог, Part, ціни, залишки, резерви та план до/після однакові. Єдиний POST від сторінок — read-only batch guidance; авторизація створює звичайні локальні сесії. Backend regression не запускався.
- Створення працівників у fixture вимкнене чинним feature gate: перевірено його збереження, без обходу/активації. Форма створення працівника не тестувалася. Для read-only Catalogue Admin тестовий API-процес має allowlist лише існуючого synthetic owner; конфігурації Railway/акаунти/права не змінювалися.
