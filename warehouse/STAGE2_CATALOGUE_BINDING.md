## Контракти

- `DismantlingItem.id` і `catalog_key` залишаються стабільними для старих маршрутів та receipt.
  `Vehicle.dismantling_v3.catalogue_item_bindings` зберігає послідовність прив’язок за ID позиції.
  Остання версія зв’язує modification, PRD, manufacturer і source SHA.
  Після повного читання артикулів вона містить підтверджені supplier/article ключі та OEM-докази.
  Порожня остання версія позначає відсутність активної прив’язки в новому snapshot.
- Перехід 126480 → 126481 при PRD 106 створює нову прив’язку.
  Нові receipt записують якір джерельної версії в чинну операцію `dismantling_receipt`.
  Історичні receipt продовжують відкриватися за чинним зв’язком позиції зі складом.
- `global-dismantling` повертає `item_bindings`, `catalogue_oems` і статус legacy OEM для користувачів із правом перегляду складу.
  `Part.oem_number` сумісно оновлюється тільки для придатної автоматичної каталожної проєкції зі свіжим доказом.
  Timeout і неповні артикули не очищають значення. Старий номер без поточного доказу відображається зі статусом `historical`.
  Ручний і фізично підтверджений OEM захищені. PATCH характеристик підтримує явне `confirm_physical_oem`, включно з підтвердженням того самого номера.
- `expected_selection_revision` дозволяє виявити паралельний вибір і перехід A → B → A.
  Поле опційне для legacy-клієнтів. Повтор успішної команди повертає збережений результат.
  Worker перевіряє ревізію до запису після мережевого читання.
