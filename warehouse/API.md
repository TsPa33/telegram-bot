# Warehouse REST API v1

Base path: `/api/v1`. OpenAPI generated by FastAPI: `/openapi.json`, interactive docs: `/docs`. No CarPot authentication or production services are used.

## Authentication

Public `GET /auth/options` reports whether registration is enabled. In staging it is closed by default; the operator creates their own real account interactively. Staging mutations additionally require the exact configured HTTPS `Origin`, including login/logout. See [RAILWAY_STAGING.md](RAILWAY_STAGING.md).

`POST /auth/register` accepts `{name,email,password}` and returns `{user,csrf_token}` with session/CSRF cookies (201). `POST /auth/login` accepts `{email,password}` and returns the same contract. Password length 12–128. `GET /auth/me` returns `{id,name,email}`. `POST /auth/logout` revokes the current session and returns 204.

All remaining endpoints require the `warehouse_session` HttpOnly cookie. All authenticated POST/PUT requests also require `X-CSRF-Token` from login/registration or the `warehouse_csrf` cookie. Cookies last 7 days and use SameSite=Strict. Use a same-origin client/proxy. No CORS wildcard is enabled.

## Filtering and pagination

List endpoints return `{items,total,offset,limit}` (audit returns items/total). Most accept `offset>=0`, `limit=1..200` (default 100; categories supports up to 10000). Stable ordering is timestamp then ID. Audit sorts newest first.

- Vehicles: `q` searches make/model/VIN/donor ID; `status`, `archived`.
- Parts/inventory: `q` searches name/OEM/article/location/serial; `vehicle_id`, `category_id`, `condition`, `availability`, `location`, `in_stock`, `archived`.
- Categories: `q`, `archived`.
- Audit: `type`, `vehicle_id`, `part_id`, `actor_id`, ISO-8601 `date_from`/`date_to` (inclusive). Send timezone-aware timestamps; browser converts local dates to UTC bounds.
- Archive: `entity`, `offset`, `limit`.

## Stock operation contract

```json
{"type":"receipt","quantity":2,"reason":"Підтверджене надходження після демонтажу"}
```

`type`: `receipt`, `write_off`, `reserve`, `release`, `correction`, `transfer`. Quantity is a positive integer for the first four; correction sets a nonnegative absolute balance. Transfer requires a nonempty `location`; quantity is unused. Reason is required, 3–2000 characters.

Part response includes `quantity`, `reserved_quantity`, derived `available_quantity`. Transactions lock the part row and enforce reserved ≤ quantity. Individual items require a serial number and allow quantity ≤1. Reservations cannot be spent by write-offs. Failed operations leave no balance changes or completed audit events.

Bulk body: `{ids:[...],action:"archive"|"restore"|"transfer",reason:"...",location:"..."}`. All selected records must belong to the account. The whole batch rolls back on failure.

## Validation and history

- 401: missing/expired session or invalid login.
- 403: missing/mismatched CSRF token.
- 404: missing record or record owned by another account.
- 409: balance conflict, duplicate unique identifiers, archived operation target, missing imported taxonomy, or conflicting import keys.
- 413: oversized file.
- 422: invalid input, malformed import hierarchy, unsupported image.
- 429: local authentication rate limit exceeded.

Unknown input fields are forbidden. Decimal money values can be supplied as strings; use exact decimal arithmetic in integrations. Part updates are full card updates with defaults, not PATCH. Do not send balance fields. Operations have no update/delete endpoint; a PostgreSQL trigger also rejects UPDATE/DELETE. Use a new correcting operation with a reason to correct stock.

UI catalog import contract and accounting definitions are described in [README.md](README.md). No business data is seeded.
