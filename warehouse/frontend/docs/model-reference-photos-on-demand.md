# Demand-driven transparent model photo library — 2026-11-26

Draft PR #588. No staging deployment, no provider calls, no new actual model photos. Previous manually reviewed static manifest remains optional; opaque JPEG processing is no longer accepted for reference cards. The example Mustang is not registered.

## Candidate implementation
- Explicit staging-only flag WAREHOUSE_MODEL_PHOTO_ENABLED=true and existing absolute durable WAREHOUSE_MODEL_PHOTO_DIR required. Separate SQLite file, no Warehouse schema change. Worker scans committed active donor identities in bounded pages with SELECT-only transaction and 3-second statement timeout. This discovers existing and newly added donors without blocking intake. One worker per shared Linux volume lock, at most 12 provider attempts per UTC day, 3 attempts per exact normalized make/model/generation/year, six-hour retry interval. Same exact identity reused; broader generation/year reuse still needs reviewed coverage metadata. Provider key sends only make/model/generation/year; no VIN/account/stock. No provider request unless separately approved.
- Provider integration is a contract, not a connected source: WAREHOUSE_MODEL_PHOTO_PROVIDER_URL (HTTPS), WAREHOUSE_MODEL_PHOTO_PROVIDER_TOKEN, WAREHOUSE_MODEL_PHOTO_PROVIDER_APPROVED=true. POST normalized identity; response identity must exactly match and contain kind=real_photo, commercial_use=true, derivatives_allowed=true, identity_reviewed=true, attribution, source_url, license_url, license, image_base64 (PNG/WebP with genuine alpha). Contract assumes source performs background segmentation and visual/rights verification. No actual provider selected, connected or tested; no paid API enabled. Pillow validates alpha and size and normalizes to transparent WebP. A provider claim alone is not independent proof of visual accuracy or rights.
- List/detail expose same-origin reference_image only when ready; existing own donor gallery preserved. Card uses the reference photo on existing layout, with linked attribution and neutral missing state; list refresh needed to see newly processed photos. Runtime metadata is batched per page; bytes lazy loaded. Existing card donor-photo priority still pending. No arbitrary URL fetching from user input.

## Acceptance gates
Configure dedicated persistent storage and approved real-image cutout source; verify no data disclosure and actual photo rights, provider limits, visually compare source model against donor, verify all current active models with measured distinct count. Run backend and frontend CI, update old browser expectations from generic fallbacks and run responsive visual tests. Check style/CSP, route permissions, owner isolation, same-origin URLs and recovery across restart. No release until gates complete. Feature off by default; production not in scope.
