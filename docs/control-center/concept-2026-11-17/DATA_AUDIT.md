## 1. Що означає 34 / 10

Підтверджений ланцюжок:
`control_directory.read_batch → entitlements.usage/state → snapshot → company_view → CompanyPreview`.
CRM не виконує власний COUNT усіх авто, а повторно використовує Warehouse domain policy.

Формула `usage.vehicles` — кількість **унікальних зайнятих донорних одиниць**:

1. Усі неархівні Vehicle цього workspace.
2. Донори, прив'язані до Part із quantity > 0 **або** reserved_quantity > 0,
   незалежно від архівності Vehicle. Запит Part також не відсікає архівні частини.
3. За увімкнених entitlement rules враховується і збережене походження DonorProvenance.
4. IDs об'єднуються множиною: багато деталей одного донора не множать використання.

Тому архівний донор із залишком/резервом продовжує займати квоту. Архівування авто
саме по собі не звільняє місткість. Чистий архівний донор, не задіяний у залишках,
до occupied не входить. Це підтверджене правило продукту, а не доведений баг CRM.

`state.vehicle_capacity` = місткість обраного чинного base/trial (або base у grace)
+ сума додаткових addon, чинних на момент розрахунку. Для Standard базова місткість
10, місць працівників 5. Прострочені/future addon не додаються; addon без обраного
base/trial/grace не створює доступ. Відсутність декомпозиції addon в CRM **не означає**,
що addon ігнорується в числі місткості.

`usage.employees` рахує лише активні дочірні accounts, без власника. Перелік people
містить власника та всіх працівників, включно з вимкненими. Ці показники мають різний
зміст і не повинні мати одну назву.

**Висновок щодо скриншота:** 34 означає тарифне використання, 10 — розраховану
місткість у snapshot. Якщо обидві величини актуальні й повні, перевищення становить
24. Не встановлено, скільки з конкретних 34 є неархівними або архівними донорами,
чи були куплені пакети та які інтервали застосовувалися в цей момент. Скриншот не є
доказом current snapshot; приховані дані конкретної компанії недоступні цьому аудиту.

Перевищення може зберігатися після downgrade/expiry пакета або в compatibility/
dry_run режимі. `enforced()` перевіряє feature policy і workspace.mode, а guard
обмежує нові дії, не видаляє існуючі дані. Фактичний режим цієї компанії не перевірено.
Немає підстав автоматично «виправляти» 34 або підвищувати тариф.

Рекомендація: перейменувати показник на «Тарифна місткість автомобілів», додати коротке
пояснення складу, показати перевищення окремо. Для деталізації потрібен окремий
дозволений read-only агрегат: total / nonarchived / occupied-archived / deduplicated
usage / активні addon / mode / час розрахунку. Жодних ID або контактів у звіті.
На цьому етапі такий endpoint чи SQL не виконувався і не додавався.

## 2. Статуси: підтверджена семантична проблема

| Поточне значення | Що доводить код | Як подавати у CRM |
| --- | --- | --- |
| ACTIVE / «Оплачено» | Чинний базовий entitlement interval | Чинний тарифний період; оплату перевіряти окремо |
| TRIAL | Чинний trial; domain paid=true дозволяє операції | Пробний доступ; не платна підписка |
| GRACE | Base завершився менш як 72 години тому; paid=true | Пільговий період; не нова оплата |
| EXPIRED | Відповідний період завершено | Період завершено; дозволені операції залежать від policy |
| FREE / «Безкоштовний» | Немає обраного active/past base у projection, зокрема можливий future interval | Без чинного тарифного періоду; не називати безкоштовним планом без продуктового правила |
| UNKNOWN / access_incomplete | Немає entitlement projection / достовірного контексту | Недостатньо даних; не FREE і не несплата |

`paid` у Warehouse — історична назва операційного allow-флага, не доказ транзакції.
CRM зараз мапить ACTIVE на «Оплачено» в `src/control/api.ts`; підтверджено ризик
хибного фінансового висновку. Адаптер коректно замінює початковий FREE на UNKNOWN,
коли projection відсутня; цей захист потрібно зберегти.

Рекомендовані незалежні осі: тарифний стан, можливість конкретних операцій,
перевіреність оплати та достовірність/актуальність даних. Compatibility/enforcement
та дозволені після expiry операції не можна звести до одного «активний/заблокований».
Відсутній Billing link не означає, що немає тарифного періоду або клієнт не платив.
Не показувати MRR, revenue, платні підписки або нуль оплат із неповного джерела.

## 3. Синхронізація та зв'язки — спостережені агрегати

Останній прочитаний успішний sweep: **17.11.2026 08:31:28 за Києвом**
(`2026-11-17T06:31:28.526702+00:00`). Перед ним є успішний sweep о 08:26:28.
Вік останнього snapshot на момент читання — приблизно дві хвилини, менше порога
15 хвилин; freshness_seconds=0 — вік у момент завершення sweep, не «завжди нуль».

| Показник | Спостережено |
| --- | ---: |
| Реальні staging workspace-компанії | 5 |
| Власники / працівники у people | 5 / 2 |
| Перевірені Warehouse links | 5 |
| Перевірені Billing links | 0 |
| Billing-unlinked компанії | 5 |
| Конфлікти / некоректні links | 0 / 0 |
| Збережені demo / demo у реальному каталозі | 5 / 0 |
| Покриття | sweep_complete |
| last_error | null |

Лічильник owners — root DIRECTOR accounts, не кількість унікальних юридичних осіб
усієї екосистеми. People-count працівників не доводить, що всі вони активні.
Унікальність directory identity забезпечує UNIQUE(environment, workspace_id),
а source identity — UNIQUE(system, environment, entity_type, source_id). Нуль
invalid_links підтверджує цілісність перевірених агрегатом company/environment
зв'язків, але не є повним аудитом дедуплікації фізичних клієнтів між продуктами.

Запити джерела signed HTTPS; Warehouse handler використовує REPEATABLE READ READ
ONLY і короткі timeout. Не було ручного sync або жодної мутації в цьому аудиті;
спостерігалися лише чинні автоматичні refresh. Метадані Railway позначають stderr
як severity=error, хоча повідомлення INFO; last_error=null — це не source failure.

Залишаються обмеження: tombstones не реалізовані, зниклі source rows можуть лишатися
історичними/stale; sweep_complete не є гарантією live census. Необхідні окремі правила
subscription binding/cohorts і фінансове джерело. Не мерджити клієнтів за email/name.

## 4. Бізнес-активність

Адаптер рахує max(Operation.created_at) для workspace, а last_login_at передає
окремо. Покриття лише Warehouse stock operations; це не повна активність екосистеми
і не DAU/MAU людей. Відсутня подія не означає неактивного клієнта. Денна серія для
графіка не повертається поточним API; у концепції 01 графік був синтетичною ілюстрацією; у фінальному Review 02 його вилучено.
