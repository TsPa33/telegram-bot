# CarPot Local Aleto v1.1

## Стан
- Перевірено `TsPa33/telegram-bot`, гілку `feature/carpot-vin-auto-staging-20261127`, SHA `dfbecea75347fce2a74be58af48818d2dc3e35d1`, суміжні гілки та доступні релізи. Windows GUI v1.0.0 і вхідні файли користувача відсутні. Код репозиторію не змінювався.
- Підготовлено `audit_sources.py` для Python 3.12. Він інвентаризує схему й кількість рядків SQLite та заголовки, кількість записів і помилки ширини CSV. SQLite відновлює журнал лише в тимчасовій копії. Локальна перевірка пройшла на синтетичній SQLite з WAL та CSV із кирилицею і багаторядковим полем.
- Наявні точки інтеграції Warehouse: `GET /api/v1/vehicles/vin/decode`, `GET /api/v1/vehicles/vin/resolution`, `GET /api/v1/vehicles/vin/catalogue-candidates`, `source-models`, `source-modifications`. Перевірити їх з авторизованим staging-сеансом перед інтеграцією.
- `warehouse/backend/app/services/catalogue_format.py` визначає `ImportRow` і обмеження завантаження 16 MiB та 50 000 рядків. Експорт має перевіряти обидві межі.

## Потрібні матеріали
ZIP із вихідним кодом v1.0.0, файлами збірки й копіями `aleto.sqlite3`, `local_aleto.sqlite3`, `parts.csv`. Перед копіюванням закрити настільний застосунок. Якщо біля SQLite лишилися відповідні WAL-файли, включити їх. Не включати секрети чи сесії.

## Далі
Перевірити фактичні схеми та показники, визначити чинний GUI/HTTP entry point, зафіксувати джерела й правила ідемпотентної міграції, розширити наявний застосунок, виконати тести й зібрати Windows-пакет. Приймальні тести з реальними файлами, Windows, Aleto та авторизованим Catalogue/VIN API ще не виконано.

## Після отримання ZIP v1.0
Отримано `carpot_local_aleto.pyw`, Windows-запускач і інструкцію. Архів не містить реальних SQLite або CSV. У попередній v1.1 розширено Tkinter GUI та SQLite v1.0, додано резервну копію перед оновленням схеми, злиття окремої бази відомої схеми без дублювання, список авто, NHTSA vPIC, фільтри, історію цін та оновлення відомих сторінок. Два Linux unit-тести пройшли. Windows-приймання, авторизований Catalogue/VIN API, старий довільний CSV/SQLite та перевірка CSV за ImportRow залишаються відкритими.

## Каскад і VIN API
`067a159110e84e27f44fa4ca1edb8a2318366813` використано як базу. Додано каскад через наявні GET-маршрути Oracle directory у Warehouse Staging, річний фільтр, локальний кеш і збереження вибраного Oracle ID. VIN використовує штатний staging VIN endpoint за наявності сесії або NHTSA vPIC за явним запитом. Сесію не збережено на диск. Результат не є підтвердженням сумісності.
П’ять автотестів пройшли в Linux. Каскад і VIN API перевірено з імітацією відповідей. Джерела користувача відсутні в сеансі. Реальна міграція, запуск на Windows і авторизована LIVE-перевірка відкриті.
