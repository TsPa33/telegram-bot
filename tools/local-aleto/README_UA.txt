CarPot Local Aleto 1.1 — попередня збірка

Розпакуйте всі файли разом і двічі натисніть ЗАПУСТИТИ_CARPOT.cmd.
Потрібен Python 3.12 для Windows із Tkinter. Сторонніх пакетів немає.

Сумісна база v1.0 у %LOCALAPPDATA%\CarPot\LocalAleto відкривається зі створенням
SQLite-резервної копії перед оновленням схеми. Закрийте старий застосунок перед
відкриттям нової версії. Кнопка «Імпорт SQLite v1.0» приймає копію з відомою схемою
jobs/pages/parts. Якщо копія має WAL, покладіть його поряд. Імпорт не змінює джерело.

«Каталог CarPot» відкриває каскад марка → модель → рік → модифікація. Перший
запит просить увійти до Warehouse Staging. Дані входу та сесія залишаються в
пам’яті. Для повторного пошуку без мережі позначте «З локального кешу» і
використайте ті самі параметри. Кеш містить лише сторінки довідника.
Натисніть «Вибрати модифікацію», перевірте дані та збережіть авто.

VIN читається через авторизований Warehouse Staging, а без сесії — через
NHTSA vPIC після явного введення VIN. Перевірте дані й натисніть «Зберегти авто».
VIN-декодування не підтверджує модифікацію Oracle. Для збору використовується наявний клієнт Aleto v1.0.
«Оновити ціни» повторно перевіряє збережені сторінки вибраного завдання.
«Підготувати CSV» формує пакети у форматі експорту v2 з версії 1.0.
Публікацію контролює користувач через чинну форму Warehouse.

Цю збірку перевірено автоматизованими тестами на синтетичній SQLite в Linux.
Windows GUI, живі VIN/Aleto-запити й реальні файли користувача ще не перевірено.
Міграція старих SQLite/CSV невідомої структури залишається відкритою.
Автоматизовані тести: python -m unittest -v
