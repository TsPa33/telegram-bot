# CarPot — етап 1: локальний VIN/source metadata audit

**Статус:** read-only інструмент підготовлено; на комп'ютері власника ще не запущено. Він **не** доводить, що в джерелі є індивідуальні VIN.

## Мета

У локальній MySQL `td1q2018` знайти потенційні колонки з VIN, chassis/frame/WMI/VDS/VIS та технічними характеристиками автомобілів: рік, тип, двигун, кузов, КПП. Зіставлення з каталожними модифікаціями стане можливим після перевірки реальних зв'язків і прикладів.

Каталожний `passanger_cars.id` — **ідентифікатор модифікації, не VIN**. Не можна автоматично застосовувати характеристику однієї модифікації до конкретного VIN без доказу відповідності.

## Запуск на Windows PowerShell

1. Переконайтеся, що локальний MySQL працює, а у `C:\CarPot\telegram-bot` є актуальна гілка `feature/carpot-local-vin-metadata-audit-20261119`. Якщо використовується інша папка checkout — вкажіть її.
2. Виконайте (пароль не публікуйте):

```powershell
cd C:\CarPot\telegram-bot
$env:SOURCE_HOST = "127.0.0.1"
$env:SOURCE_PORT = "3306"
$env:SOURCE_USER = "root"
$env:SOURCE_DATABASE = "td1q2018"
# Якщо MySQL має пароль: $env:SOURCE_PASSWORD = Read-Host "MySQL password"
py -3 -m pip install PyMySQL
py -3 .\catalogue\local_vin_metadata_audit.py --output C:\CarPot\vin_source_metadata_20261119.json
```

За відсутності пароля змінну `SOURCE_PASSWORD` можна не задавати; за необхідності використовуйте чинні локальні облікові дані. Скрипт жорстко обмежено локальним хостом і джерелом `td1q2018`.

**Файл результату:** `C:\CarPot\vin_source_metadata_20261119.json`. Перед повторним запуском використайте інше ім'я файлу (записи не перезаписуються).

## Межі та безпека

- Читаються **лише** `SELECT DATABASE(), VERSION()` та метадані `information_schema.COLUMNS/TABLES/STATISTICS`.
- Немає `SELECT *` із вихідних таблиць, повних сканувань, індексування, DDL, UPDATE/INSERT, експорту VIN-значень, доступу до Railway або платних API.
- JSON зберігає назви таблиць, полів, індекси та приблизні розміри, але не паролі та не персональні VIN.
- Нуль збігів за назвами VIN не означає, що VIN відсутні: дані можуть бути зашифровані, зберігатися в неочевидних колонках або у файлах поза MySQL.

## Наступна дія після результату

1. Розглянути `vin_name_candidate_tables` і `vehicle_candidate_tables`.
2. Окремо перевірити лише фактичні відповідні таблиці, їхні зв'язки й безпечні обмежені вибірки.
3. Побудувати таблицю відповідності: підтверджений VIN / VIN-діапазон → source modification ID → виробник, модель, атрибути. Відсутні / конфліктні характеристики залишити невідомими.
4. Тільки після цього впровадити local-first enrichment у Warehouse. Якщо прямого VIN немає, використати локальні модифікації **лише** як перевірку / підказку після зовнішнього декодування.
